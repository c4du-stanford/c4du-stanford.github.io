Walkthrough: two people, one project

A real run of CoSci, the Rubin Co-Scientist, with two people on one project. Pat records a conversation, CoSci learns from it, and Pat shares one rule with the project's shared lab by typing cosci share. Kim's agent, on another machine, finds the rule and where Pat said it, but cannot open Pat's conversation.

It ran against real private GitHub repos with Claude Code 2.1.304 and its Sonnet model. Logins, names, paths and repos were renamed (Pat is pat, Kim is kim, the shared lab is lab/shared-repo, Pat's private lab pat/cosci-notes) and project and thread names replaced with generic labels. Hashes, times and wording are as they came out, except one sentence naming a real colleague, which was reworded; some outputs are summarised.

The setup

  • lab/shared-repo is the project's shared lab. Someone on the project created its repo on GitHub and gave both people write access, so both install with --shared (a first member can also create it at install). Its key on every machine is shared-repo.
  • Pat's private lab is pat/cosci-notes on Pat's own GitHub account (key cosci-notes).
  • Kim chose a local-only private lab (local/notes, key notes) that never leaves Kim's machine; one on GitHub works the same way.

Pat installs:

~/.cosci-src/install.sh --shared lab/shared-repo --private pat/cosci-notes --handle pat --learn claude

This run installed from a clone of the cosci repo; the installer from the install page in the README takes the same options after the file name (bash cosci-install.sh --shared …). The summary lists both labs as (cloned), in the format the guide shows, and learn claude.

1. Pat records a thread

Pat starts cosci, opens a thread and says two things about the project:

cosci open-thread project-setup

For the project: the alert stream comes from ANTARES, and the analysis notebooks live under notebooks/ in the project repo.

One more rule: the lens-model priors are set in config/priors.yaml; nobody hard-codes priors inside a notebook.

The new thread was created in Pat's private lab. After each reply the agent showed the recorded turn and its footer; this is the second:

## Tuesday October 20 2026 · 1:57 AM PDT · pats-claude-code (claude-code)

Understood: lens-model priors live in config/priors.yaml, and no notebook hard-codes them.

⚙ Claude Sonnet 5.5 in Claude Code 2.1.304 · careful · effort unavailable

[committed: 8d11af1d3dfe files=2]

→ committed 1c4444f to discussions/project-setup/project-setup-0.md

pat/cosci-notes on GitHub now has three commits, all by Pat's git identity; the thread file holds Pat's two turns and the agent's two:

2. cosci learns from it

Learning starts in the background after a call on the current thread, at most once every 30 minutes per lab. It runs Pat's own claude command with no tools over the turns in Pat's private lab it has not read yet, and writes what it learned into that lab. Here the pass was started by hand with the server's command, which runs the knowledge-base tool tools/brain.py:

python3 ~/.cosci/tools/brain.py --config ~/.cosci-data/config.yml learn --home cosci-notes

Add --estimate to see what a pass would send, with no model call.

The pass made one model call over 4 turns and pushed one commit, 4b5a33ad586f brain: learned from 4 turns, which cosci status reports:

    cosci-notes        private   pat/cosci-notes                  ~/.cosci-data/pat__cosci-notes  (up to date)
                     learn: learned from 4 turn(s) at 2026-10-20T09:01:43Z; commit 4b5a33ad586f, pushed

When Pat's agent next opened the thread, its outline listed three statements, each with an id, a standing (whose words it rests on) and a locator pointing to the exact turn where it was said:

  • cosci-notes/project-setup/priors-in-config-yaml: "Set lens-model priors in config/priors.yaml; never hard-code priors inside a notebook." (pat's words) cosci-notes@1c4444f97fe4:discussions/project-setup/project-setup-0.md#t2~14bb2b8580bc
  • cosci-notes/project-setup/alert-stream-antares: "The project's alert stream comes from ANTARES." (pat's words) …#t0~26e4f76d9b70
  • cosci-notes/project-setup/notebooks-location: "The analysis notebooks live under notebooks/ in the project repo." (pat's words) …#t0~26e4f76d9b70

All three are in Pat's private knowledge base; nobody else sees them yet.

3. Pat shares one statement

The priors rule matters to everyone. In the private thread, Pat types:

cosci share cosci-notes/project-setup/priors-in-config-yaml

The agent, having no tool for sharing, relayed the line through cosci_dispatch and reported:

  • shared cosci-notes/project-setup/priors-in-config-yaml with shared-repo as shared-repo/project-setup/priors-in-config-yaml
  • shared by pat; pushed

The shared lab got two commits in one push, 1c310c7b90f2 and then 412489d946db. The first holds the passage the rule came from, so the statement in the second can point to a commit that already holds it. That copy holds only the passage and when it was said:

Recorded Tuesday October 20 2026 · 1:57 AM PDT.

One more rule: the lens-model priors are set in config/priors.yaml; nobody hard-codes priors inside a notebook.

Pat's private lab keeps a line saying what was shared, when and where (commit 402f83e). The other two statements stay private. Typing the same cosci share again changes nothing, and says so.

4. Kim installs

~/.cosci-src/install.sh --shared lab/shared-repo --private local/notes --handle kim --git-name 'Kim Example' --git-email kim@example.org --learn off
  handle    kim   (agents sign as kims-claude-code and kims-codex; commits are by Kim Example <kim@example.org>)
  repos     shared-repo      shared    lab/shared-repo                  ~/.cosci-data/lab__shared-repo  (cloned)
            notes            private   local only                       ~/.cosci-data/local__notes  (created)

The shared lab's key is shared-repo on both machines because it comes from the repo's GitHub name, so a locator written on one machine resolves on the other.

5. Kim's agent finds the rule, and where it was said

Kim starts cosci, opens a thread (cosci open-thread kim-plan, created in notes) and asks where the lens-model priors are set. The agent called cosci_context with the question and got the shared statement:

  • id shared-repo/project-setup/priors-in-config-yaml, kind instruction
  • "Set lens-model priors in config/priors.yaml; never hard-code priors inside a notebook."
  • standing: pat's words
  • source: shared-repo@1c310c7b90f2:ledger/brain/evidence/a9258dc75367.md~a9258dc75367
  • under the topic topic:shared-repo/project-setup ("Project search setup")

Opening that source (cosci_open) returned the passage from step 3, so Kim's agent can state the rule as Pat's words and quote where Pat said it.

6. Kim's agent cannot open Pat's private turn

The shared copy keeps the statement's original link into Pat's private lab, which opens only on Pat's machine, where the cosci-notes repo is configured. Kim's agent tried to open it:

cosci-notes@1c4444f97fe4:discussions/project-setup/project-setup-0.md#t2~14bb2b8580bc

and was refused with permission_denied, reason repo-not-configured: thread kim-plan may not read cosci-notes, because no lab with that key is configured on Kim's machine, and another person's private lab cannot be read.

cosci_read on the same locator gives the same refusal. Kim's machine has no lab with that key, so there is nothing to grant: what Pat shared is all Kim's agent can see of Pat's work.

7. What agents learn about cosci itself reaches everyone

Agents also record in the shared lab what they find about how cosci behaves, under "What agents have learned about running cosci". In the same run, Pat's machine recorded one with cosci_observe, under idea:shared-repo/cosci/itself ("How cosci itself behaves"): a statement shared from one machine reached a second machine's cosci_context on its next read, with no write from the second machine. Its standing was "observed by claude-code-agent on cosci 0.1.0, 2026-10-20", and it was pushed as commit 86e635a.

Kim's clone was one commit behind; Kim's next cosci_context fetched first and returned the finding, with no write from Kim. Findings are written as by "claude-code-agent", never a person, and are refused if they name you, a private lab or thread, or your home folder.

threads.md explains the knowledge base, permissions and sharing; skills.md lists the commands.
