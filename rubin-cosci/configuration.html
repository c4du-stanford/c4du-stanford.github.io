Install

Configuration

cosci keeps two settings files on each machine:

  • ~/.cosci-data/config.yml lists your labs' repos and their read and write permissions.
  • ~/.cosci/settings.json holds your login, learning settings and update source.

Neither file is committed: both contain this machine's paths. Re-running the installer or joining a lab preserves existing entries. You can also edit config.yml by hand. Joining through an agent's MCP tool refreshes that session immediately; restart a running agent after changes made from another process or by hand.

Names in the examples are made up: pat is an example GitHub login, and OWNER/SHARED-REPO stands for a shared lab's repo.

A fresh install creates your private lab on this machine only (local/notes, at ~/.cosci-data/local__notes); --create-private creates <login>/cosci-notes on GitHub instead. An existing installation keeps its configured repos and locations. No GitHub data repo is renamed or moved.

repos and their keys

repos: maps a key to a repo. The key is the name you type (cosci new-thread shared-repo/<name>, cosci grant shared-repo read), the name in a thread's permission file, and the first part of every locator and statement id that cites the repo (shared-repo@1c310c7b90f2:…, shared-repo/project-setup/priors-in-config-yaml).

A GitHub repo's key is its name, lowercased, with characters other than letters, digits and hyphens turned into hyphens (OWNER/SHARED-REPO is shared-repo); you do not choose it. Every machine gives a shared lab the same key, so citations resolve across machines. You can configure several shared labs, each with its own key.

If another configured repo already holds that name, a shared newcomer is refused, since colleagues cite it by its plain name; first remove or rename the entry that holds it. A private newcomer gets owner__name (pat__notes), with a warning that citations of it made on other machines will not resolve here.

A repo named manager is always owner__manager. A local-only repo keeps the name you give it (local/<name>). A key never changes once configured.

Each entry has:

  • repo: the full name, owner/name, or local/<name> for a repo that exists only on this machine.
  • layer: private (a private lab), shared (a shared lab) or harness (below).
  • remote: the GitHub owner/repo the clone syncs with, or null for a local-only repo.
  • path: the clone on disk.
  • thread_defaults: the permission (none, read or read-write) a thread stored in this repo starts with on self (this repo), others (every other data repo), manager (the installed cosci code) and shared (a shared lab). Widening one widens every thread stored in the repo; grant per thread with cosci grant.

layer

  • private: your private lab, by default local/notes on this machine only; on GitHub (--create-private), <login>/cosci-notes on your personal account, because an organisation's owners can read every private repo in it. It holds your threads, logged in full, and the private knowledge base learned from them. Threads stored here may read your shared labs.
  • shared: a shared lab's GitHub repo. It holds the lab's threads and knowledge base, what members share from their private labs, and what agents have learned about running cosci. A thread stored here can never read a private lab, whatever its grants say.
  • harness: the installed cosci code at ~/.cosci (the manager entry). Threads can always read it and never write it.

principals and timezone

principals lists the GitHub logins whose words count as the people's words in the knowledge base ("pat's words"). The installer adds yours. cosci share and notes about running cosci refuse text naming any of them.

timezone is the IANA zone turn headers are shown in (America/Los_Angeles, Europe/Paris, UTC). The installer writes this machine's zone or the one you pass with --timezone. Stored times are explicit, so changing the zone changes only how new headers read.

defaults

defaults.default_write: deny denies writes unless a thread's permission file says otherwise. Leave it.

capture

capture.commentary sets what the Claude Code capture hooks keep of an agent's narration while it works:

  • skip-short (the installer's choice): keep each final answer and any substantial interim message, and drop short tool preambles.
  • record (when the key is absent): keep every visible message.
  • skip: keep only the final answer.

capture.commentary_min_chars (default 280) is the length that counts as substantial.

Adding a lab

The guide shows joining through the terminal, an agent or Python; each uses the same join operation. OWNER/SHARED-REPO below is a placeholder for your lab's repo, and pat is an example login. In your terminal:

cosci join OWNER/SHARED-REPO
cosci join pat/research-notes --private
cosci join local/papers --private

The default is a shared lab. --private adds it as your private lab; the older --layer private and --layer shared options also work. A GitHub repo must already exist and be accessible using your git credentials. Joining never creates one. A local/ repo stays on your machine and has no GitHub remote.

Joining copies the repo to your data directory, sets your commit identity and adds it to config.yml. A GitHub repo's key comes from its name, so colleagues use matching keys in citations. --protocol ssh selects SSH. --key can name a local-only repo; for a GitHub repo it may only repeat the derived key.

cosci has no create command. One member starts the lab, either with the installer's --create-shared option or by creating an empty private repo on GitHub and joining it, and gives colleagues write access on GitHub; everyone else joins it. You can join several labs; see working with several labs. You can install with just your private lab and join a shared lab later. A successful MCP join makes the lab available in that session immediately. After joining from Bash or Python, restart any agent session already running in another process.

Joining does not widen an existing thread's write permissions. To hold a conversation in the shared lab, type cosci new-thread shared-repo/<thread-name> to your agent. See threads for access grants and sharing.

To change your login or setup, re-run the installer or type cosci reset in an agent session. See the Python API guide for direct imports and joining from a script.

settings.json

~/.cosci/settings.json holds:

  • handle: your GitHub login, lowercased. Your agents sign as <handle>s-claude-code and <handle>s-codex.
  • learn: claude, codex or off (below).
  • capture_hooks: true by default. Claude Code sessions then get capture hooks through --settings, a silent backstop that records a reply the agent forgot to append. Codex reads hooks only from ~/.codex, which cosci never edits, so Codex sessions have none.
  • git_name, git_email: the identity your commits use, from your git config or --git-name / --git-email. The installer sets it on each data repo.
  • gh: the GitHub CLI cosci's own git commands sign in to GitHub through, when you signed in during the guided install and kept that sign-in for CoSci only (CoSci's copy at ~/.cosci/gh/bin/gh, or your own gh). Absent otherwise: git then uses your own credential setup.
  • python_api_pth: where the Python API is registered.
  • protocol: https or ssh, for clones.
  • install_url: for an install from the install page, the release repo cosci update fetches with git (https://github.com/stanford-developers/rubin-cosci-install); null for a clone install.
  • source: for a clone install, the clone cosci update reads; null for an install from the install page. Re-running the installer the other way switches between the two.
  • release_ref, version, installed_at: what is installed.
  • data_root, config: where the data repos and config.yml are.

Learning

A call on the current thread may start a background learning pass for the repo the thread is stored in. A pass:

  1. Reads the repo's unread turns.
  2. Asks a model what they establish.
  3. Checks every proposed entry in code: it must cite existing passages and say correctly whose words they are, or it is dropped.
  4. Publishes the result to the same repo in one commit, pushed to GitHub.

It learns only a repo's own turns into that repo's knowledge base.

The model call is your own agent command, run non-interactively as you:

  • learn: claude runs claude -p --output-format json --model sonnet with no tools, no MCP servers, no saved session and all hooks disabled, in an empty temporary folder, with the prompt on stdin.
  • learn: codex runs codex exec --json --ephemeral --sandbox read-only with Codex's default model.
  • learn: off never starts one.

The default is claude when claude is on your PATH, else off; choose with --learn at install time or edit settings.json.

The calls are billed to your own Claude or Codex account:

  • A pass starts at most once every 30 minutes per repo, never while the previous one runs.
  • It makes no model call when there are no unread turns.
  • A few new turns take one call (in the end-to-end run, 4 turns took one call to Sonnet); a long backlog takes more.
  • Each call has a time limit: 420 seconds, longer for very long prompts.

To see what a pass would take before it runs:

python3 ~/.cosci/tools/brain.py --config ~/.cosci-data/config.yml learn --home cosci-notes --estimate

It counts the turns, passes, calls and prompt size, and calls no model. A failed pass never affects your session. It is logged, and cosci status shows each repo's last pass (learned from 4 turn(s) at …; commit 4b5a33ad586f, pushed, nothing new to learn, or the error).

Environment variables

cosci sets these per session in ~/.cosci/run/mcp-<pid>.json (Claude Code) or the -c mcp_servers.cosci.env override (Codex). Do not set them yourself:

VariableMeaning
COSCI_CONFIGThe config.yml to use.
COSCI_HANDLEThe agent's handle in turn headers, e.g. pats-claude-code.
COSCI_HUMAN_HANDLEYour handle, how your turns are attributed.
COSCI_HARNESSclaude-code or codex, recorded in each turn's runtime line.
COSCI_HARNESS_REF, COSCI_ROOTThe harness version the session runs, and where.
COSCI_REPOThe lab a thread created without one is stored in: your private lab when you have one.
COSCI_LEARN, COSCI_LEARN_LOGThe learner setting and its failure log.

You may set these in the shell you start cosci from:

VariableMeaning
COSCI_PYTHONA Python of your own that runs cosci and its server, used as it is; it must have PyYAML. Default: CoSci's own environment, ~/.cosci/venv/bin/python (or python3 on your PATH when there is none).
COSCI_GHThe gh cosci's git commands sign in to GitHub through. The installer remembers its choice as gh in settings.json, so you rarely set this.
COSCI_CLAUDE, COSCI_CODEXThe claude or codex executable to start, when not the one on your PATH.
COSCI_GIT_TIMEOUTSeconds a clone or fetch by install.sh, cosci join or cosci status --fetch may take (default 300).
COSCI_NO_PULL1 to never fetch: reads and writes use the clones as they are.
COSCI_FRESHEN_EVERYSeconds between fetches of one clone before a read (default 60).
COSCI_PROMPT_CONTEXT_SECONDSHow long the prompt hook waits for the knowledge base's context (default 30).
COSCI_LEARN_MODELThe model the learner asks for. Defaults: sonnet (Claude) and Codex's default model.

None is a secret. cosci reads no credential from the environment; git uses your own credential setup, or asks gh when COSCI_GH (or the gh setting) names one.
