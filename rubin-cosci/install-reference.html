Installing

For the normal install, see the quickstart. This page is for options, scripted installs and special cases. Options go after the file: bash cosci-install.sh --help lists them all.

Where to get the installer

The install page is https://c4du-stanford.github.io/rubin-cosci/install/. It opens only for GitHub accounts with access to the private repo stanford-developers/rubin-cosci-install. Stanford members sign in with Stanford. If it shows 404 or a sign-in loop, ask the person who invited you to add your GitHub account.

  • Download for Mac gives CoSci-Install.dmg. It opens as the Install CoSci folder, with cosci-install.sh and How to install CoSci. Run bash "/Volumes/Install CoSci/cosci-install.sh" in Terminal.
  • Download for the RSP or Linux gives cosci-install.sh: one file with CoSci inside. It checks itself against a checksum before installing.
  • With git access to GitHub already set up (agents, scripts):
git clone --depth 1 https://github.com/stanford-developers/rubin-cosci-install ~/cosci-release && bash ~/cosci-release/cosci-install.sh

Downloaded twice on a Mac? The second copy opens as Install CoSci 1. Eject the older Install CoSci in Finder's sidebar first, or drag the newest cosci-install.sh into Terminal after typing bash .

Updates. cosci update fetches the newest release with your GitHub sign-in, the same access the page needs. If it can't, download the newest installer from the page and run it. Your labs and settings are kept.

Why Terminal, not a double-click app

CoSci is not signed by Apple. macOS blocks an unsigned app opened from a download, but not a file run with bash in Terminal. So the Mac download holds no app. The CoSci app the installer writes into ~/Applications is made on your Mac and opens normally.

The guided install and --yes

Run in a terminal, the installer is guided:

  • On a Mac, the questions open in the CoSci setup window. Add --terminal to answer in the terminal instead.
  • On Linux and the Rubin Science Platform, they are asked in the terminal.
  • With --yes (or -y), or with no terminal (an agent or a script), it asks nothing. The options alone decide.

Each question has an option that answers it in advance:

  • Coding agent: --agent claude|codex|both|none
  • Shared labs: --shared OWNER/SHARED-REPO to join, --create-shared OWNER/SHARED-REPO to start one
  • Private labs: --private OWNER/REPO (one you already have; repeat it for several, and --private local/notes keeps one on this computer too), --create-private (a new <login>/cosci-notes), or --local (no GitHub at all)
  • Background learning: --learn claude|codex|off
  • The cosci command in Terminal: --no-path leaves your shell's startup files alone

The review step shows your choices as options. The same options plus --yes repeat the install without questions.

What the guided install can run for you, always shown first and only after a yes:

  • Apple's command line tools on a new Mac: xcode-select --install.
  • Claude Code or Codex: its maker's installer, its update, and its sign-in with your own account.
  • The GitHub CLI, if you have no gh: a private copy in ~/.cosci/gh, checked against GitHub's published checksum.
  • The GitHub sign-in: gh auth login --web, with a one-time code you paste at https://github.com/login/device.
  • Accepting a lab invitation waiting for you on GitHub.

The agents and gh keep their own sign-ins. CoSci never reads, asks for or stores a password or token.

CoSci's Python environment

The installer makes CoSci's own Python environment at ~/.cosci/venv, with PyYAML (and pywebview on a Mac, for the app). Your own Python is not changed. cosci uninstall removes it.

  • If it can't be made on Debian or Ubuntu, install the python3-venv package and run the installer again.
  • If pywebview can't be installed, the rest still installs; the summary shows the command that adds it.
  • To use your own Python instead, set COSCI_PYTHON (it must already have PyYAML; CoSci installs nothing into it):
COSCI_PYTHON=/path/to/python3 bash cosci-install.sh

Starting a project

One member starts a shared lab, once. Two ways:

  • At install: bash cosci-install.sh --create-shared OWNER/SHARED-REPO. It creates the private repo on GitHub. It refuses a repo that already exists.
  • Later: create an empty private repo on GitHub (on the web, or gh repo create OWNER/SHARED-REPO --private), then cosci join OWNER/SHARED-REPO. CoSci gives it its first commit.

Then give each colleague write access on GitHub (the repo's Settings → Collaborators). Every recorded turn is pushed, so read access is not enough. They join from the setup window, from Join a lab… in the CoSci window, or with cosci join OWNER/SHARED-REPO.

More in the guide: joining, starting a lab, several labs.

Your private lab on GitHub

  • A new one: bash cosci-install.sh --create-private makes a private <login>/cosci-notes on your personal account. It is backed up and reachable from your other computers.
  • One you already have (from another computer): bash cosci-install.sh --private OWNER/REPO.

Keep it on your personal account: organization owners can read private repos in their organization.

Installing from a clone

With access to the application repo:

git clone https://github.com/c4du-stanford/rubin-cosci ~/.cosci-src
~/.cosci-src/install.sh

cosci update then follows that clone's release tags.

No GitHub at all

bash cosci-install.sh --local --handle pat

Everything stays on this computer. Shared labs are local too (--shared local/<name>). pat is an example name.

All options

--private, --create-private, --shared, --create-shared, --local, --handle, --git-name, --git-email, --install-root, --data-root, --learn claude|codex|off, --timezone, --protocol https|ssh, --no-link, --no-path, --agent claude|codex|both|none, --terminal, --yes (-y, --no-input) and --install-url.

Re-running the installer keeps your labs and settings. --local can't be combined with --create-shared. For the full text, run bash cosci-install.sh --help.
