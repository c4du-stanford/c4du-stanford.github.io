Uninstall

One command removes cosci. Your data repos (threads and knowledge bases, here and on GitHub) stay.

1. Remove the harness and the command

cosci uninstall

It says what it removes and keeps, then asks. After installing from the install page on a Mac it prints, for example:

this removes the harness at ~/.cosci (with CoSci's own Python environment) (with CoSci's own GitHub CLI), the launcher link ~/.local/bin/cosci, the CoSci app ~/Applications/CoSci.app, the Python API registration ~/.cosci/venv/lib/python3.9/site-packages/cosci.pth, the PATH line it added to ~/.zprofile, the session run files, the search index ~/.cache/cosci/brain-index (built from your repos), the workspace ~/.cosci-data/workspace and harness worktrees under ~/.cosci-data/harnesses
  the harness's git history goes with it: 0 mutation commit(s), 0 tagged harness(es), branches base, main
  to keep it: git clone /Users/pat/.cosci <somewhere> first
kept, untouched: every data repo (~/.cosci-data/local__notes, ~/.cosci-data/owner__shared-repo) and ~/.cosci-data/config.yml; nothing on GitHub is touched
continue? [y/N] y
done; reinstall any time: download the installer from the install page, https://c4du-stanford.github.io/rubin-cosci/install/

It lists only what is there: the GitHub CLI appears only if the guided install put a copy in ~/.cosci/gh, and the app only on a Mac. Paths are the actual ones; the Python registration is removed only when it belongs to this installation.

After a clone install the kept line also names the source clone ~/.cosci-src, and the last line says to reinstall with install.sh from it.

cosci uninstall -y skips the question. If the cosci command is already gone, ~/.cosci/bin/cosci uninstall does the same, or ~/.cosci-src/uninstall.sh after a clone install.

The search index holds text from your turns, so it goes too. If you pointed COSCI_BRAIN_CACHE elsewhere, delete that folder yourself. The harness's history holds your changes and tags; to keep them, clone ~/.cosci first, as the message says.

If the installer added ~/.local/bin to your PATH, uninstall takes that line (marked # added by the cosci installer) out of your shell's startup file again. cosci itself never wrote under ~/.claude or ~/.codex, so nothing of cosci's is there to clean.

Python, the GitHub CLI and your sign-ins

CoSci's own Python environment, ~/.cosci/venv, with PyYAML and pywebview, goes with the harness, and so does the Python API registration inside it. If you installed with COSCI_PYTHON, that Python and its packages are left as they are; only cosci's registration is removed from it.

CoSci's copy of the GitHub CLI, ~/.cosci/gh, goes too. If you answered yes to Also use it for your other git work on GitHub?, uninstall also removes the git settings that pointed git at that copy (in your global git configuration), so git no longer tries to run it.

Your GitHub sign-in itself stays in gh's own storage (the keychain on a Mac). To remove it, run gh auth logout before uninstalling (~/.cosci/gh/bin/gh auth logout for CoSci's copy), or revoke it on github.com under Settings > Applications. The agents you installed or signed in to, Claude Code and Codex, are yours and stay as they are.

2. Check it is gone

ls ~/.cosci            # No such file or directory
command -v cosci       # prints nothing

What is kept

On disk: every data repo under ~/.cosci-data/<owner>__<repo>, the configuration ~/.cosci-data/config.yml, the learner log ~/.cosci-data/learn.log and, after a clone install, the source clone ~/.cosci-src. Your private lab and your shared labs on GitHub are untouched. The data repos are plain git repos; read them with any editor, or run:

git -C ~/.cosci-data/local__notes log --stat

Run the install again any time (download the installer from the install page and run it, or install.sh from your clone) and cosci picks the repos up again, reporting each as (up to date) or (exists). To remove a local clone, delete it; its GitHub repo stays.
