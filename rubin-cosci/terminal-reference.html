Install

In a terminal

You can manage records directly in Bash without starting an agent. The cosci thread commands use your installed configuration and git identity, and return JSON. They enforce the same read and write permissions as the MCP tools. To list the available commands and their arguments:

cosci thread --help
cosci thread append --help

Examples:

cosci thread list
cosci thread new-thread --thread plan --home-repo cosci-notes
cosci thread status --thread plan
cosci thread digest --thread plan
cosci thread append --thread plan --human-text "What next?" --agent-text "Check the fit."
cosci thread permissions --thread plan

append also accepts --human-file and --agent-file for text saved in files. Explicit configuration and identity arguments override the installed defaults. To put a new thread in a particular repo, add --home-repo <repo-key>.

A thread's own conversation

cosci --thread <lab>/<thread> (or cosci codex --thread …) starts the agent on that thread's own conversation, the one the CoSci window's chat and terminal pane continue, with the thread open:

cosci --thread cosci-notes/project-setup

The window's Copy the command for Terminal gives this line. While the session runs it holds the thread, so the window's chat and terminal wait (and say where it is open) until you quit it; the window still shows each turn as it is recorded. A conversation is resumed only by the agent that started it: a Claude Code conversation by Claude Code, a Codex one by Codex (once Codex has given its id).

Recording sessions

Recording can be paused for one session without pausing other sessions using the thread. Give your terminal workflow a name with COSCI_SURFACE_SESSION_ID and use the same name on its commands:

COSCI_SURFACE_SESSION_ID=terminal-notes cosci thread set-band --thread plan --state closed
COSCI_SURFACE_SESSION_ID=terminal-notes cosci thread status --thread plan
COSCI_SURFACE_SESSION_ID=terminal-notes cosci thread set-band --thread plan --state open

Use that same prefix for append calls belonging to this workflow. Closing recording requires a session name; the command reports an error if it is missing. An unnamed terminal call cannot close a different session's recording.

Access and sharing

From your own terminal you can issue the human commands for permissions, recording and sharing. For example:

cosci thread grant --thread plan --target-repo shared-repo --permission read

In an agent session, the agent must use the MCP tools and relay access and sharing commands only when you type them. cosci thread refuses to run inside a cosci agent session. The thread guide explains the permission rules, and the Python API guide covers direct programmatic access.
