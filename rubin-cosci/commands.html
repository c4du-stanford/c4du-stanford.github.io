This file is generated from ccm_core/dispatch.py. Every verb below is also available as a typed MCP tool. docs/threads.md explains what each one means. The command form is cosci <verb> [args].

You type these and the agent relays them. A bare help works too.

Help

  • help, help <topic>, cosci help [topic] - print the command reference.

Setup

  • cosci join <owner/repo> [--private] [--key <key>] - join a shared lab's existing repo; use --private for your own private lab. Joins an existing GitHub repo or local/<name> with your git credentials. It is available in this session immediately. Joining does not create a GitHub repo.
  • cosci reset - re-run the installer (cosci update, or the install line) to change the handle or where records are kept; settings are in ~/.cosci/settings.json.

Threads - opening and reading

  • cosci open-thread <name> - open thread <name>, creating it if it does not exist. Spoken forms that also work: open-thread <name>, open thread <name>. Use <repo>/<name> to target a specific data repo.
  • cosci new-thread <name> - create a new thread with the current turn as its first; fails if it exists. Spoken forms that also work: new thread: <name>, discussion: <name>. Use <repo>/<name> to choose the repo it is stored in.
  • cosci close-thread - close the current thread and go back to ordinary, unrecorded conversation. Spoken forms that also work: close-thread, close thread.
  • cosci list - list active threads (in all configured repos, or in one repo). Spoken forms that also work: what discussions are open?, what discussions are open.
  • cosci status - show the status of the current thread.
  • cosci catchup [--limit N] - where the current thread stands, in one call: status (band, permissions, next_action, pending warnings), the last N turns (default 12) as 300-character excerpts, and the latest human and agent turns in full; the best first read.

Threads - recording for someone else

  • cosci as <handle>: <message> - record one human turn as <handle>, keeping <message> word for word. Spoken forms that also work: as <handle>: <message>.

Threads - recording earlier turns

  • cosci include-last <N> - add this session's last N earlier turns, from the history the harness supplies. Spoken forms that also work: include the last N turns.
  • cosci include-from "<phrase>" - add this session's earlier turns from the one containing the quoted phrase, from the history the harness supplies. Spoken forms that also work: include from "<phrase>".
  • cosci log-as <name> - record the current exchange as thread <name> from this turn on; earlier turns only with include-last or include-from. Spoken forms that also work: log this as thread <name>.

Threads - commit footer control

  • cosci quiet - hide the commit footers for this session until unquiet (recording continues). Spoken forms that also work: quiet.
  • cosci unquiet - resume showing commit footers for this session. Spoken forms that also work: unquiet.

Threads - the band (recording on or off)

  • cosci close-band - keep the thread open but pause recording (close the band) until open-band.
  • cosci open-band - resume recording turns on the current thread (open the band).
  • cosci set-band <open|closed> - set the band of the current thread to open (recording) or closed (paused).

Threads - permissions

  • cosci permissions - show what the current thread may read and write, and whether each permission is granted explicitly or inherited from a default.
  • cosci grant <repo> <none|read|read-write> [--as <human-handle>] - change the current thread's permission on one repo by editing its permission file. This edits the thread's permission file, which decides what it may write, so only you make a grant: type it yourself. An agent may relay the command, as with cosci close-band. No agent tool can make a grant. Granting read-write means this thread's content can reach that repo. cosci tidy lists every such grant.

Knowledge base

  • cosci share <statement-id> [<statement-id> ...] [--to <lab>] [--as <human-handle>] - share statements from your private lab's knowledge base with a shared lab, where its members and their agents can read them. Sharing is your act, so you type it yourself. An agent may suggest something to share and relay the command. No agent tool can share. Type it in a thread of your private lab. Each statement goes with the passage it came from, so the lab can see its source. Text holding your handle, home folder or a private lab or thread name is refused. Sharing the same statement twice changes nothing. --to names the shared lab when you have joined more than one.

Maintenance

  • cosci tidy [--thread <name>] [--apply] - audit every configured repo for stale markers, ledger growth, chunk-status drift and missing permission files, and list every cross-repo write grant; repairs nothing unless --apply is given. Tidy writes only state local to your clone or files inside the repo being tidied. It never copies content between repos.

Surfaces

  • cosci surface-ack - no longer required; kept so older clients that acknowledge do not error.

In your terminal

  • cosci join <owner/repo> [--private] [--key <key>] - join a shared lab's existing repo; use --private for your own private lab.
  • cosci thread <command> [args] - manage records directly, without an agent; use cosci thread --help for commands.

Direct terminal commands

How a command reaches the engine

Claude Code calls the typed cosci_* tools of the cosci MCP server directly. Anything you type as cosci <verb> ... is checked by cosci_dispatch first. That check makes a command like cosci close-band count as your act.
