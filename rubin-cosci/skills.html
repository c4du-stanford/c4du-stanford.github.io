Install

Slash commands and typed commands

In a Claude Code session started with cosci, every cosci command is a slash command named /cosci:<verb>. Type /cosci and the completion menu lists them with argument hints; pick one and add arguments, for example /cosci:open-thread project-setup.

In Codex, and optionally in Claude Code, type the command as words (cosci open-thread project-setup) and the agent relays it to cosci.

How they reach a session

Each slash command is a skill: a folder under ~/.cosci/skills/ with a SKILL.md telling the agent which cosci tools to call and in what order: open a thread before recording, show the footer every time, never change the band, a grant or a share on its own.

cosci hands the folder to Claude Code as a plugin named cosci for that one session (claude --plugin-dir ~/.cosci/plugin …), which is why the commands start with /cosci:. Nothing is copied into ~/.claude/skills/ or a project's .claude/skills/, and a session started with plain claude has none of them.

In the end-to-end run, an cosci session listed all 30 /cosci: commands of that release and 24 cosci tools, and /cosci:status ran the cosci status tool. /cosci:improve makes 31 now.

Plugins are read at session start: after cosci update or a skill edit under ~/.cosci/skills/, start a new cosci session.

Commands only you run

These skills carry disable-model-invocation: true, so Claude Code never runs them on its own; they run only when you type the slash command, which counts as typing the cosci command. cosci harness check fails if the band, grant, share or improve skills lose that line.

  • The band: /cosci:close-band, /cosci:open-band, /cosci:set-band. The agent never decides that an exchange should go unrecorded.
  • Permission grants: /cosci:grant, which edits the thread's permission file.
  • Sharing a statement with a shared lab: /cosci:share.
  • Also yours alone: /cosci:close-thread, /cosci:as, /cosci:include-last, /cosci:include-from, /cosci:log-as, /cosci:quiet, /cosci:unquiet, /cosci:mode, /cosci:tidy, /cosci:reset, /cosci:improve.

Typed as words (cosci close-band, cosci grant …, cosci share …), they go through the cosci dispatcher; the agent has no separate tool for them.

Every command

Arguments are the hints Claude Code shows; square brackets mark optional parts. A command missing a needed argument says what it needs: /cosci:open-thread alone lists your threads and asks which one, and never guesses a name.

Threads

  • /cosci:start: Says whether a thread and the band are open; with no thread open, lists threads and asks which to open.
  • /cosci:open-thread [<repo>/]<name>: Opens a thread (created if new) and catches up on it.
  • /cosci:new-thread [<repo>/]<name>: Creates a thread; this turn is its opening turn. Refuses a name that exists.
  • /cosci:close-thread: Closes the current thread; back to unrecorded conversation.
  • /cosci:list [<repo>]: Active threads, each with the repo it is stored in and last activity.
  • /cosci:status: Current thread, band, permissions, last turns, anything not yet pushed.
  • /cosci:catchup [--limit N]: One-call orientation: recent turns in excerpt, the latest human and agent turns in full.
  • /cosci:digest [<thread> | <repo>/<thread>] [--limit N]: A short digest of a thread, newest first, paged backward.
  • /cosci:read <turn index | turn hash | locator ...> [in <repo>/<thread>]: Full turn text, or the passages locators point to.
  • /cosci:record: Records the current reply now and shows its footer.

Recording and the band

  • /cosci:close-band: Pauses recording on the current thread.
  • /cosci:open-band: Resumes recording.
  • /cosci:set-band <open|closed>: Sets the band.
  • /cosci:quiet: Hides the commit footers; recording is unchanged.
  • /cosci:unquiet: Shows them again.
  • /cosci:as <handle>: <message>: Records one human turn in that person's words, verbatim.
  • /cosci:include-last <N>: Adds the last N turns of this session from before recording started.
  • /cosci:include-from "<phrase>": Adds this session's turns from the one containing the phrase.
  • /cosci:log-as [<repo>/]<name>: Records the current exchange as a new thread, from this turn forward.

Permissions

  • /cosci:permissions: What the current thread may read and write, and where each permission came from.
  • /cosci:grant <repo> <none|read|read-write> [--as <human-handle>]: Changes the thread's permission on one repo.

The knowledge base

  • /cosci:context [<question or topic> | <outline id>]: What the project already knows: the outline, its statements with whose words they rest on, open tensions; or one outline node, walked up and down.
  • /cosci:search <query> [; <query> ...]: Ranked passages from every lab the thread may read, with locators to cite.
  • /cosci:mode <quick|careful|away> [your words]: Records how you want the thread worked, in your words.
  • /cosci:observe <what was learned about running cosci>: Records a finding about running cosci in your shared lab.
  • /cosci:share <statement-id> [<statement-id> ...] [--to <lab>] [--as <human-handle>]: Shares statements from your private lab's knowledge base with a shared lab.

Maintenance

  • /cosci:tidy [--thread <name>] [--apply]: Audits the repos and lists every cross-repo write grant. Repairs only with --apply.
  • /cosci:join <owner/repo> [--private] [--key <key>]: Joins an existing lab's repo, as a shared lab by default or as your private lab with --private; usable in this session at once.
  • /cosci:reset: Changes the handle or labs, by re-running the installer or cosci join, driven in the session.
  • /cosci:improve [--since <date>] [--threads <a,b>] [--dry-run]: Proposes a few small changes to the harness prompts and skills, drawn from your recorded threads, on a new local branch to try or delete (improve.md).
  • /cosci:harness [list | check | pending | tag <name> | discard | use <ref> | branch <name> | merge <ref> | diff | show]: Manages the harness under ~/.cosci (harness.md).
  • /cosci:help [topic]: The command reference.

In Codex

Codex has no per-session slash commands; cosci codex gives it only the cosci tools and instructions. Type commands as words: cosci open-thread project-setup, cosci status, cosci close-band, cosci grant shared-repo read, cosci share <id>. The agent relays each through the cosci dispatcher.

The typed commands are listed in commands.md: help, open-thread, new-thread, close-thread, list, status, catchup, as, include-last, include-from, log-as, quiet, unquiet, close-band, open-band, set-band, permissions, grant, share, tidy, join and reset. cosci improve runs from a terminal (improve.md).

Context, search, read, digest, record, mode and observe are not typed verbs. In Codex, ask for them in words ("what does the project already know about the priors?", "note this as a cosci finding") and the agent calls the matching cosci tool.

The knowledge base, briefly

When a thread opens, the agent receives the knowledge base's outline: the ideas in each readable lab, from its root down to what this thread touches. Each statement says whose words it rests on ("pat's words", "confirmed by pat", "inferred from pat's words") and has a locator to cite. Before acting on something only inferred, the agent asks you in one line and records your answer. See threads.md.
