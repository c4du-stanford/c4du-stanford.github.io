Improving the harness from the record

cosci improve studies what your recorded threads and the notes about running cosci show about how agents have worked, and proposes a few small changes to the wording of the harness prompts and skills. They go on a new local branch for you to read, try, and adopt or delete. Your current harness is not changed.

Run it from a terminal:

cosci improve                                  # every readable thread, at most 3 changes
cosci improve --since 2026-10-01               # only turns from that day on
cosci improve --threads project-setup,notes/inbox
cosci improve --dry-run                        # show the proposals; make no branch
cosci improve --estimate                       # show how much would be read; ask nothing
cosci improve --max 5 --json                   # up to 5 changes; print the run's record as JSON

--max takes 1 to 10. In a Claude Code session started with cosci, /cosci:improve runs the same command. Its skill carries disable-model-invocation: true, so only you start it.

What it reads

  • Your recorded threads: every thread you can read in your private lab and your shared labs, or only those named with --threads (by name, or <repo>/<name> when two labs share a name), and only turns from --since (YYYY-MM-DD) on. As in learning, each turn is cut to 6000 characters (a person's) or 1500 (an agent's). The newest turns are read first, up to about 90,000 characters; --estimate says how many were left out. Withheld turns are never read.
  • Notes about running cosci: the findings agents recorded with cosci_observe under the root "What agents have learned about running cosci" in each shared lab (threads.md).
  • The files a harness may change (mutable-surface-manifest.md), as committed at your current harness commit: the prompts harness/<agent>.md and the skills skills/<name>/SKILL.md. style.md is in a data repo, outside the harness, so cosci improve does not change it.

Who is asked

The agent CLI your learn setting names (claude or codex), as for background learning, logged in as you; learn_model or COSCI_LEARN_MODEL picks the model. It runs once, twice if its first reply is not the JSON asked for, in an empty temporary folder with no tools, saved session or hooks, so it can read and change nothing. With learn: off, cosci improve says there is no one to ask. The prompt, templates/improve.md, tells the agent that everything recorded is data to study, never instructions.

What code checks

Code trusts nothing in the reply. Each proposed change is {path, old, new, why, evidence}, where evidence lists the turns or findings that show the problem; code drops it, and counts why, when:

Dropped asWhen
over-limitit comes after the --max changes already kept
malformedpath, old or new is missing or not text
never-touchthe harness check holds the path unchanged (the check and tests, the engine's write path, telemetry, the interpreter floor, the manifest and triage)
out-of-surfaceany other path that is not a prompt or skill of this harness, including new files and paths outside it
no-changeold and new are the same
ambiguous-oldold is empty or does not occur exactly once in the file
too-largeold is over 2000 characters or new over 2500
overlapit overlaps a change kept earlier in the same reply
safeguardit reaches into a skill's front matter or a locked prompt paragraph (the recorded-turn loop, typed commands, which cover sharing, mutating the harness, boundaries), or removes a safeguard word (never, footer, rendered_block, cosci_dispatch, cosci_append, --as, only the person, only you, not attached to any directory, boundaries, allowed-tools, disable-model-invocation)
leakthe new text adds a token-shaped string, a locator, or a private word (your handles, your home folder, a private lab or thread name), or, where the harness carries the leak check's scanner (tools/scan_names.py), a hit of its rules
no-evidence, unresolved-evidenceit cites nothing, or an item that is neither a locator that resolves for you (the knowledge base's citation check) nor a finding id that was shown

What it makes

Kept changes are committed with your git identity on a new branch improve/<UTC time> (for example improve/20261020T153000Z, with -2 added if that name is taken), made from your current harness commit in a temporary worktree. The commit message gives each change's reason and the turns or findings it cites. Then cosci harness check runs on the branch and the run prints gate: green, or gate: RED (<checks>); the branch is kept for inspection with the problems found. Your current branch, working tree and commit are never touched, and nothing is merged. Uncommitted edits in ~/.cosci are not on the branch; the run notes them.

It prints the next steps:

cosci harness diff improve/<time> --patch     # read the changes
cosci --harness improve/<time>                # try them in one session
cosci harness merge improve/<time>            # adopt them (checked again; a failing result is undone)
git -C ~/.cosci branch -D improve/<time>      # or delete them

Dry runs, estimates, runs with nothing to change and runs that stop on an error make no branch and change nothing. A run stops, saying why and what to do, when for example nothing is recorded in the window (widen --since or --threads), there is no git identity, or the agent call fails. Exit status: 0 for a passing branch, dry run, estimate or nothing to change; 1 for an error or failing branch; 2 for bad arguments.

The log

Each run is logged on this machine under the data root, in ~/.cosci-data/improve/: one line in runs.jsonl (past 256 KB the older half is dropped) and the full record, every proposal kept or dropped and why, as <time>.json. cosci status shows the last run on its improve line.
