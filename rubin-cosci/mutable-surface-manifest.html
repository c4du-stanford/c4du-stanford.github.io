cosci mutable-surface manifest

--- title: "cosci mutable-surface manifest" status: active tags: [cosci, governance, manifest] last_updated: "2026-10-20" ---

The boundary for changes to an installed cosci harness (~/.cosci, see harness.md): what may change, what never may, and what enforces each line. An agent in a cosci session takes its authority from this file; an edit outside the may-touch list is invalid. A change to never-touch code fails the harness check (cosci harness check), so cosci harness tag refuses it.

The invariant

The agent never applies a change on its own. Every change takes one path: the person decides the edit → it is applied under ~/.cosci → the check passes (cosci harness check) → the person commits it (cosci harness tag <name> --as <handle>).

An agent acts as the person's hands: once told what to change, it may apply the edit, run the check and show the diff (cosci harness pending --patch). It never tags, merges, switches (cosci harness use) or discards a harness unprompted. cosci improve puts its drafts on a branch improve/<time>; only the person merges them (improve.md).

An engineer changes these in the cosci repository, as an ordinary commit with tests, and they reach people in a release (cosci update).

Enforcement

  • Every commit goes through the check. cosci harness tag and cosci harness merge run tools/check_harness.py first and refuse when it fails; a merge result that fails is undone.
  • Never-touch code. The never-touch check fails if tools/check_harness.py, tests/, ccm_core/engine.py, ccm_core/config.py, mcp/server.py, ccm_core/telemetry.py, ccm_pyfloor.py, this manifest or triage.md differ from the base release, so such a change cannot be tagged.
  • Permissions. default_write: deny and person-only grants protect them. The agent has no grant tool, and the grant skill carries disable-model-invocation: true, enforced by skills-coverage.
  • Recorded turns and the local config are outside the harness, so the check skips them; the rules above protect them.
  • Audit. A tag made with --as <handle> names the authorizing person in the tag message, and the harness's git history keeps every change.

Changing this manifest

Only an engineer changes it, in the cosci repository, with the reasoning in the commit message, and it reaches installed harnesses in a release. An agent may only ask for a change, as prose in a thread.
