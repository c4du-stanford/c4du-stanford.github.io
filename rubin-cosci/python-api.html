Install

Python API

The installer makes ccm_core importable with the Python it installed cosci with: by default CoSci's own Python environment, ~/.cosci/venv/bin/python. Run your scripts with that interpreter, for example ~/.cosci/venv/bin/python my_script.py, or start it with no script for an interactive session. You can use the same records from Python, the CLI or an agent connected through MCP. They share the permission rules, git identity and local configuration.

Join a repo

from ccm_core import join_repo

result = join_repo("OWNER/SHARED-REPO")
print(result)

Replace OWNER/SHARED-REPO with your lab's existing GitHub repo, which you must be able to access; it is a placeholder, not a real repo. The default is to join it as a shared lab. Its key is the lower-case repo name (shared-repo). To add a repo as your private lab:

result = join_repo("pat/research-notes", shared=False)  # pat is an example login

The result is a dictionary with the repo's key, local path, join status and any notes. Joining copies the repo to your data directory and adds it to config.yml. Rejoining preserves existing records. It does not create a GitHub repo (to start a new lab, see the guide), call a model, or grant an existing thread permission to write there.

The function uses your installed settings by default. For a separate installation, pass config_path, install_root and data_root explicitly. Optional git_name, git_email and protocol override the configured commit identity and clone method. key can name a local-only repo; GitHub repo keys are derived from their names so colleagues' citations agree.

Python environments

cosci writes a cosci.pth file in the site-packages directory of the Python that installed it. The file points to the installed application, so imports use its current code. cosci status shows the registration path on its python line.

  • The default install uses CoSci's own environment, so the file is in ~/.cosci/venv/lib/python3.X/site-packages/, and import ccm_core works with ~/.cosci/venv/bin/python. Your own python3, and other virtual environments or conda environments, do not read it. To add packages for your scripts there, use ~/.cosci/venv/bin/python -m pip install <package>; they are removed with it when you uninstall.
  • With COSCI_PYTHON, the installer uses that Python as it is (it must already have PyYAML). The file goes in that Python's virtual environment when it runs in one, and otherwise in its user site-packages. import ccm_core then works with that Python. See the install reference.

To see an interpreter's search paths:

~/.cosci/venv/bin/python -m site

If Python reports ModuleNotFoundError: No module named 'ccm_core', check that installation succeeded and that you are running the interpreter cosci was installed with. An unwritable registration directory is an installation error.

cosci uninstall removes its own Python registration while keeping your data repos. With the default install it removes ~/.cosci/venv as well; a Python named by COSCI_PYTHON, and its packages, stay as they are.

Other record operations

ccm_core also exports configuration, thread, recording and permission functions. Read the exports in ccm_core/__init__.py for their names and the source functions for their parameters. These operations use the same engine as the MCP tools and the direct record CLI, available with cosci thread --help.

Calls that only manage or read records do not need an agent. Operations that ask a model to learn or propose instruction changes use your configured model account. In an agent session, the agent must use the MCP tools and follow the restrictions on recording, access grants and sharing; the direct API is also available for your own programs.
