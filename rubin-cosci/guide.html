Install

Guide

CoSci keeps a research group's conversations, notes and plots in labs, and learns from them. You and your agent can then catch up on what the group knows, with every statement linked to where it was said.

New here? Start with the quickstart.

Words used here

  • Lab: a place where CoSci keeps records. Each lab is a git repository.
  • Private lab: your own lab. Only you read it. It lives on your computer, or in a private repository on your GitHub account. You can have several.
  • Shared lab: a lab a group shares, as a private GitHub repository. Its members are the repository's collaborators.
  • Thread: a named conversation in one lab, recorded turn by turn.
  • Note: your own words posted to a thread, with no agent.
  • Knowledge base: the statements CoSci learns from a lab's threads. Each one links to where it was said.
  • Share: move something from your private lab into a shared lab: a note, an excerpt, a statement.

Labs hold records, not your research code. Your code stays where it is.

1. Before you install

You don't need to prepare anything on a Mac: the installer checks for what's missing and offers to set it up. On Linux or the Rubin Science Platform you need git and Python 3.9 or newer; both are usually there.

A coding agent is optional. CoSci works with Claude Code or Codex, signed in with your own account. Without one, you read your labs and post notes. You can add an agent any time.

GitHub is needed only for shared labs. If you have no account, make one at https://github.com/signup. The installer signs you in with a one-time code.

2. Install cosci

See the quickstart for the steps. In short: open the install page, download, and run the installer. On a Mac it opens the CoSci setup window.

What the installer asks

The setup window has these pages. On Linux and the Rubin Science Platform the same questions are asked in the terminal; press Enter to take each default.

  1. This Mac. What it found: the system, git, Python, GitHub's tool, Claude Code, Codex. Nothing changes here.
  2. Coding agent. Claude Code, Codex, both, or none. For each one you choose, it offers to install it, update it and sign in. You sign in with your own account; CoSci never sees it.
  3. GitHub. If you're already signed in, it says so. Otherwise Get my code shows a one-time code (like ABCD-1234). Paste it at https://github.com/login/device and click Authorize.
  4. Labs. Two parts that work the same way. Your private labs come first: one on this Mac is already added; labs on your GitHub account are listed with Add; or type one as owner/name; or start a new one on GitHub. You can have several. Shared labs come second: labs you were invited to are listed with Accept and add or Add. Or type a lab as owner/name and click Check and add. You can also start a new shared lab. If you type your own repository as a shared lab, the window asks whether you meant your private lab.
  5. Settings. Background learning (on with your agent, or off), with a checkbox for each lab you chose: each lab keeps its own knowledge base inside the lab, saved with it, so a shared lab's members see it. Also whether you can type cosci in Terminal.
  6. Review. Your choices, then Install CoSci.
  7. Install. It shows each step, then Open CoSci.

Closing the window before Install CoSci installs nothing. The Guide button at the bottom left opens these guides.

Installing with an agent or a script, with no questions? See the install reference.

What is installed

  • The program: ~/.cosci, with its own Python environment. Your own Python is not changed.
  • The cosci command: ~/.local/bin/cosci.
  • Your labs and settings: ~/.cosci-data. Your private lab is ~/.cosci-data/local__notes unless you chose GitHub.
  • The CoSci app (Mac): ~/Applications/CoSci.app.
  • GitHub's tool, only if you asked for it: ~/.cosci/gh.

CoSci doesn't change your agents' own settings or add files to your projects. cosci uninstall removes the program and keeps every lab (details). Custom paths are in configuration.

3. Labs

Your private lab holds your own threads. A shared lab holds what its members put there. A conversation in a shared lab can't read your private lab. Content moves from private to shared only when you share it.

Join an existing lab

  1. Ask the lab's owner to give your GitHub account write access to its repository. Every recorded turn is pushed, so you need write access.
  2. Accept the invitation (from GitHub's email, or at https://github.com/notifications).
  3. Join it: in the CoSci window, Join a lab… at the bottom of the sidebar. Or in a terminal:
cosci join OWNER/SHARED-REPO

The lab's short name (its key) is the repository name in lower case: OWNER/Lensing-Lab becomes lensing-lab.

Start a new lab

One member does this, once.

  • In the CoSci window: Join a lab…, then start a new one. CoSci creates the private repository on GitHub and joins it.
  • In a terminal: gh repo create OWNER/SHARED-REPO --private, then cosci join OWNER/SHARED-REPO.

Then add members on GitHub: the repository's Settings → Collaborators, with write access. CoSci doesn't send invitations.

Work with several labs

You can join any number of shared labs. Each is a separate GitHub repository, and membership of one gives no access to another.

  • A new thread goes in the lab you start it under (in a terminal: cosci open-thread lab-a/plan; with no key it goes in your private lab).
  • A thread in your private lab can read the shared labs you joined.
  • A thread in a shared lab can't read your private lab, or another lab unless you type cosci grant lab-b read in it.
  • To put a statement in a lab: cosci share <statement-id> --to lab-b.

An agent can't share or change permissions by itself; it only relays commands you type. More in threads.

4. The CoSci window (Mac)

Open CoSci from your Applications folder, Spotlight, or cosci app in a terminal.

  • The sidebar lists your labs, each marked Private lab or Shared lab. Click a lab to open it, then a thread to read it.
  • New thread under a lab starts one there.
  • Talk: type in the box and press Return (Shift-Return for a new line). Your agent answers and the exchange is recorded. Stop (the square) stops a reply.
  • No agent: choose Just post a note under the box. Your words go in as your own turn.
  • Add a plot or a doc: the paperclip. Pick the file, write a caption, send. Images show in the thread. Files over 25 MB are refused: post a link instead.
  • Terminal, above the box, opens the same conversation as Claude Code itself. Chat goes back.
  • Copy the command for Terminal gives you one line to continue the same conversation in your own Terminal.
  • Knowledge base shows what CoSci learned in a lab, each statement linked to its source.
  • Where your stuff lives shows each lab's folder, whether it's on GitHub, and who can read it.
  • Links opens the Rubin Science Platform, GitHub and these guides.

New posts from other members show up by themselves within a few seconds. Reading works offline.

5. In a terminal

Start your agent with CoSci attached: cosci for Claude Code, cosci codex for Codex. To work in a code folder: cosci ~/code/PROJECT.

Then open a thread:

cosci open-thread project-setup

Each recorded reply ends with a receipt like → committed 6f74418 to discussions/project-setup/project-setup-0.md. It is saved on your computer and, for a lab on GitHub, pushed. not pushed yet means it is saved and will be pushed on the next write.

Try a catch-up request:

I'm joining this project. Read the lab's knowledge base and threads and explain the current approach. What should I read first, and what is still open?

Leave with /exit (Claude Code) or /quit (Codex). Everything recorded is already saved. cosci close-band pauses recording in a thread; cosci open-band resumes it.

All terminal commands are in the command reference.

6. Keep going

  • Learning: after a conversation, CoSci learns statements from it in the background, on your own agent account. Turn it off in Settings at install, or see configuration.
  • Updates: cosci update --check, then cosci update. Your labs and settings are kept. Start a new agent session afterwards.
  • Status: cosci status shows what's installed and which labs you have.
  • Improving CoSci: cosci improve proposes small changes to the agent's instructions from your experience (how).

A two-person example is in the walkthrough. Problems: troubleshooting.
